Scenario Briefing: The Leak in Logistics

You are investigating a web app run by **Global Logistics Inc**. The development team recently deployed an automated "Fetch Status" tool. This tool allows logistics partners to check internal microservices or public URL responsiveness.

The Vulnerability: The fetch mechanism does not restrict URLs to public domain patterns. This creates a classic **Server-Side Request Forgery (SSRF)** vulnerability. Because this app is hosted on an **AWS EC2 instance**, the host can communicate with the AWS link-local Instance Metadata Service (IMDS) at http://169.254.169.254.

Your Mission:

  1. Use the Fetch Status URL Tool to explore the AWS metadata service.
  2. Find the IAM role attached to the instance and extract its temporary credentials (Access Key ID and Secret Key).
  3. Load those credentials into the AWS CLI Simulator on the right.
  4. Use S3 CLI commands to locate and download the secret flag from the internal buckets.

1. Vulnerable Fetch Status Web Tool

Try querying standard sites (e.g. https://google.com) first, then try accessing the AWS link-local IMDS IP address: http://169.254.169.254/latest/meta-data/.
Output will appear here once you send a request.

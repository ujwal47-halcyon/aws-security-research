The Vulnerability: iam:PassRole + Over-Privileged Instance Profile
  1. You are logged in as developer (role: DeveloperRole).
  2. Your permissions include ec2:DescribeInstances, s3:ListBucket, and iam:PassRole.
  3. There is an EC2 instance i-0abcd1234efgh5678 with an IAM Instance Profile: EC2AdminRole.
  4. EC2AdminRole has policies: FullEC2Control (ec2:*, ssm:*) and SSMExecutionPolicy.
  5. The Flaw: The DeveloperRole has iam:PassRole without resource restrictions, allowing it to pass EC2AdminRole to any EC2 instance (or assume it directly in this simulator).
  6. Attack Path: Use POST /api/sts/assume-role with role_arn: "arn:aws:iam::123456789012:role/EC2AdminRole".
  7. Once assumed, your session has ec2:* and ssm:*. This allows accessing Secrets Manager (simulated via /api/secrets/get).
Flags to Capture:
  • FLAG 1 (Role Assumption): FLAG{aws_iam_passrole_ec2_ssm_privesc_2026} — stored in EC2AdminRole metadata.
  • FLAG 2 (Secrets Manager): DB_SECRET{aws_rds_root_pass_9981} — secret prod/database/password.
  • FLAG 3 (Secrets Manager): API_SECRET{stripe_live_key_9999a} — secret prod/api/master_key.
